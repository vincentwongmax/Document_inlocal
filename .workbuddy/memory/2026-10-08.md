### ① 點過輸入框後連點空白處往上滑

0.1.23 的 `body { min-height: 100% }` 只修好「**沒點過輸入框**」那一半。
點過輸入框之後多出**兩個持續狀態**，各自讓 iOS 一直重新對齊畫面：

- **focus zoom**（CSS 根治）：iOS 對 `font-size < 16px` 的可編輯元素會自動放大整頁，
  且 **blur 後不保證還原** → visual viewport 一直小於 layout viewport → 之後每次點畫面
  都被重新對齊。→ `src/style.css` 把「會叫出鍵盤的可編輯元素」字級一律拉到 16px
  - ⚠ 那段宣告**必須排在 `input, select, textarea { font: inherit }` 之後**
    （同特異度靠源碼順序取勝；搬到上面這條修正就整條失效，而症狀只在 iPhone 出現）
  - ⚠ **刻意不含 `<select>`**：iOS 的 select 是叫出原生滾輪選擇器（不是鍵盤）、沒有游標，
    既不會 focus zoom 也沒有游標對齊迴圈；站上的 select 都是刻意做小的膠囊控制
    （`.sel`、`.rates__addsel`、`.currow__add` 都 13px），硬套 16px 只會撐壞版面
- **游標對齊迴圈**（JS 根治）：iOS 在輸入框保持聚焦期間會持續把游標對齊到可視範圍，
  而**點空白處不會自動 blur**、鍵盤也還開著（visual viewport 被鍵盤壓短）→
  每點一下空白處就再對齊一次。
  → 新增 `src/lib/iosScrollGuard.ts`（`main.ts` 開機 `installIosScrollGuard()`）：
  `pointerdown`（capture）時，若「點在空白處（不在互動元素內）**且**當下有可編輯元素聚焦」
  → 記下當下 scrollX/scrollY → `active.blur()` → rAF×2 後把位置扶回去。
  點按鈕／連結時完全不插手；彈窗開著（`html.is-locked`）也不插手；非 iOS 整支不裝

### ② 管理分類的下拉選單滑不動

根因：`useScrollLock` 的 document 層 `touchmove` preventDefault **只放行
`opts.scrollable()` 指定的那一個元素**，而 `CategorySelect` 的 `.pop`
（z-index 95）是 **Teleport 到 body** 的、不在彈窗的 `.box` 裡
→ 手指在清單裡滑動被 preventDefault → 清單根本滑不動。

修法：`useScrollLock.ts` 新增 `scrollableAncestor()`，改成兩段判斷 ——
① `scrollable()` 指定的元素放行；② 否則往上找「**當下真的可以捲動**」的祖先
（`overflow-y` 是 auto/scroll/overlay **且** `scrollHeight > clientHeight + 1`）放行；
③ 其餘一律擋。**有溢出的都滑得動，沒溢出的都被鎖**（背景仍鎖得住）。
`scrollable` 仍值得給，但**不再是地雷**。

### ① 雙擊空白處（0.1.25 沒修好，這次補上關鍵的一層）

**0.1.25 為什麼還不夠**：它只在「當下有輸入框聚焦」時才動手（收掉它）。
可是**雙擊的第二次點擊**發生時，輸入框早就被第一次點擊收掉了 → 護欄完全沒插手，
WebKit 就把它當成一次真正的 double-tap 手勢處理（smart zoom／重新對齊 visual viewport）。

→ 加上**第一層「擋掉雙擊手勢本身」**：在「空白處」的第二次 `touchend` 上
`preventDefault()`（`touchend` 要 `{ passive: false }`）。WebKit 收不到第二個 touchend
的預設行為就組不出 double-tap —— 比只靠 `touch-action: manipulation` 直接得多。
另外兩層保留（收掉輸入框、扶正捲動位置），扶正改成 **rAF×2 ＋ ~300ms 兩次**
（因為 iOS 收鍵盤的還原動畫是非同步的，跑完可能又把畫面帶走一次）。

⚠ **我做的決定：只在空白處擋雙擊**。使用者說「無論在任何地方雙擊都不要動」，
但按鈕上的連點是合法的連續操作（計算機快速按兩下同一個數字），擋掉會把功能弄壞。
v105 有一段**對照組**專門守這個（點金額欄、點計算機數字鍵都不能被 preventDefault）。

### ⚠⚠ 寫 v105 時踩到的四個坑（都記進 CONVENTIONS 了）

1. **CDP 的觸控命中 ≠ `elementFromPoint`**：偶爾不一致（底部固定列、toast 陰影…）
   → 「找空白點」要先用一次**探測觸控**確認實際目標，不能只信 `elementFromPoint`。
2. **SweetAlert2 的 toast 會蓋住螢幕下半部，而它上面有按鈕**
   → 掃描會把 toast 的空白區誤判成空白，實際卻打在它的按鈕上。
   每次找空白點之前先等 toast 消失。
3. **順序是「先聚焦輸入框，再找空白點」**：`focus()` 會把輸入框捲進可視範圍，
   底下的內容會移動 —— 先找點再聚焦的話，那個空白點已經不是空白了。

**根因**：Chart.js 的 tooltip 有 **200ms 的 opacity 動畫**

手機上手指一點就放開／連續點，動畫停在半路 → tooltip 半透明，

- `animations.opacity.duration = 0` → 一出現就是實色
- `titleColor`／`bodyColor` 明寫白色（`Chart.defaults.color` 是灰綠，給座標軸用的）
- `displayColors: false`
- 甜甜圈的 tooltip 改 `position: 'nearest'`：預設 `average` 會壓在中心的
  「總支出／總收入」上；`nearest` 貼著手指點的位置（扇形外緣）

⚠⚠ **除錯教訓（第一版沒修好）**：一開始寫成
`Chart.defaults.plugins.tooltip.animation = { opacity: { duration: 0 } }`（**單數**），
runtime 完全不理、fade 照樣在。翻原始碼才發現 `Tooltip._resolveAnimations()` 讀的是
**`options.animations`（複數）**，而且要跟 `chart.options.animation` 同時存在才會啟用。
→ 對第三方套件做設定，要**驗 runtime 行為**（這裡用逐 rAF 採樣 canvas 像素），
不能只看文件/型別寫了什麼。

## 0.1.34（10/9）：修正快速金額子頁面「往下拉之後畫面卡死」

使用者回報：設定頁 → 快速金額 → 詳細 彈出的子頁面，用戶**往下拉**關閉（不是右上角✕），
就會「背景暗了，任何畫面都無法操作」。

### 根因（我 0.1.30 做這個子頁面時接錯的）

- `usePullToClose` 的 `onClose` 我錯接成 `backToList()`（只把內容切回清單），
  mask 的 `@click.self` 也一樣 → **子頁面從來沒有真的關掉**：暗幕留在原地、
  背景被 useScrollLock 鎖住 → 整個畫面卡死。右上角 ✕ 是 0.1.31 才加的，接得正確。

### 修法

- `onClose: () => emit('close')`、mask `@click.self="emit('close')"`——
  跟其他七個子頁面同一套語意：下拉／點暗背景＝真的收起來。
- 草稿照舊不落地（下拉關掉不會多出一顆 0 金額按鈕）。

### 測試

- v109 → **78 項全過**，新增 0.1.34 回歸：
  **合成 TouchEvent**（`new Touch` + touchstart/move×4/touchend，拖 270px）模擬
  「編輯中往下拉」→ 斷言暗幕退場＋is-locked 解除＋stored 還是 3（草稿沒落地）；
  再驗 mask click 也會真的關閉。
  ⚠ 合成手勢要 `hasTouch: true` 的 viewport，`TouchEvent`/`Touch` 才存在。
