## 0.1.83：應用鎖（Face ID／PIN 碼）

使用者需求（原話）：
「在設定頁中加入apple 的FACEID 鎖屏代碼，用戶在PWA (IPHONE) 的模式下，打開PWA 應用時，
要求用戶輸入FACEID 才能打開應用，另外加入PIN 碼模式，用戶可以在FACEID 和PIN 模式2選1，
桌面版和其他用戶就只可以用PIN 碼模式」。

### 先問過使用者的 4 個決定
1. PIN 位數 → **4–8 位自選**
2. 鎖定時機 → **切回前台超過 1 分鐘**才重鎖（重新打開 App 一定鎖）
3. Face ID 模式 → **保留 PIN 備用**
4. 忘記 PIN → **用恢復碼**（不是一鍵重置）

### 實作
- `src/lib/appLock.ts`（核心）
  - localStorage `mop-ledger.lock.v1`：`{enabled,mode,pinHash,pinSalt,pinLen,credId,recoveryHash,recoverySalt,updatedAt}`
  - PIN：PBKDF2-SHA256、12 萬次迭代、16 bytes 隨機鹽 → 只存 base64 雜湊
  - 恢復碼：10 碼（去掉 I/O/0/1），顯示成 `ABCDE-FGHJK`；只存雜湊；只顯示一次
  - Face ID：`navigator.credentials.create/get`，`authenticatorAttachment:'platform'`、
    `userVerification:'required'`、`rp.id=location.hostname`；只存 credential rawId（base64）
  - `isIOSPwa = isIOSDevice() && isStandalone` ＋ `isUserVerifyingPlatformAuthenticatorAvailable()`
    → `faceIdAvailable`（桌面/Android 只有 PIN）
  - 上鎖狀態只放**記憶體**（`unlocked`）：重新載入＝重新上鎖
  - `visibilitychange`：hidden 記時間，visible 時超過 `RELOCK_MS=60000` 才 `unlocked=false`
- `src/components/AppLock.vue`（鎖屏）
  - fixed inset:0、z-index 2000、不透明 `var(--bg)` → 蓋住整個 App
  - Face ID 模式：大按鈕＋「改用 PIN 碼」＋「忘記 PIN」；**不在載入時自動觸發**
    （WebAuthn 要手勢），另加 90 秒安全網避免按鈕卡在「驗證中…」
  - PIN 模式：自製數字鍵盤，打到 `pinLen` 位自動送出；錯→震動＋清空；⌫
  - 恢復碼：頁內輸入（不用 SweetAlert，因為 z-index 1060 < 2000 會被鎖屏蓋住）
- `src/components/LockSettings.vue`（設定頁區塊）
  - 啟用：兩次 PIN → 顯示一次性恢復碼 →（iPhone PWA）問要不要同時開 Face ID
  - 變更 PIN／開關 Face ID／重產恢復碼／關閉鎖 → **都先驗目前 PIN**
- `src/lib/alerts.ts`：新增 `askPinDialog`／`askRecoveryDialog`／`showRecoveryCodeDialog`
- `src/App.vue`：setup 同步阶段 `initAppLock()`（避免先閃內容）＋ `<AppLock v-if="isLocked" />`
- `src/views/SettingsView.vue`：在「App 圖示」與「離線與版本」之間加「應用鎖」section

### 驗證
- `.smoke/probe-lock.mjs`：20/20（啟用→重整→錯 PIN→正確 PIN→立即上鎖→恢復碼→錯恢復碼）
- `.smoke/v154.mjs`（正式守門員，**39 斷言**）：另加 PIN 4/8 位邊界、舊 PIN 錯不能改、
  localStorage 不存明文 PIN、關閉後不再鎖
- 全回歸 **78 支全過**（v70~v154）

### 部署
- 見 MEMORY.md 版本行（main／gh-pages commit）。

### 教訓
- Face ID ≠ 相機人臉辨識；Web 上只能用 WebAuthn（系統 Face ID），且**必須使用者手勢**。
- 鎖屏不要用 SweetAlert（z-index 1060 會被 2000 的鎖屏蓋住）→ 恢復碼改頁內輸入。
- 設定頁新增 section 不影響舊測試（都按文字找），但**不要新增 `<select>`**。

## 0.1.84 —— Face ID 打開 App 就自動辨識

### 需求
使用者原話：「如果用戶選擇了FACEID，應該打開APP時就直接使用FACEID，不應該要用戶再按一次
FACEID 解鎖，而且目前按了一次之後還會觸發IPHONE 的彈窗問要使用FACEID 登入嗎？
你將會使用XXXX 通行密鑰登入之類的，可否也一起簡化，直接打開APP 就FACEID 識別
(中間沒有任何步驟)--> 成功進入APP」

### 改動
- `src/lib/appLock.ts`
  - 新增 `manualLockAt`（模組級）＋ `autoFaceIdAllowed()`：`lockNow()` 會記時間，
    **5 秒內不自動跳 Face ID**（否則一按「立即上鎖」就馬上被 Face ID 解開，等於沒作用）
- `src/components/AppLock.vue`
  - `onMounted` 自動呼叫 `tryFaceId(true)`：`setTimeout(160ms)` 讓鎖屏先畫出來再跳系統面板
  - `tryFaceId(fromAuto = false)`：**自動嘗試失敗不顯示錯誤**（免得一開 App 就看到紅字）
  - 按鈕改綁 `onFaceIdClick`（**不能直接綁 `tryFaceId`**，否則 MouseEvent 會被當成 `fromAuto=true`）
  - 守衛：非 iOS 先 `await detectPlatformAuth()`，沒有平台驗證器就不自動跳
    （不然 headless／桌機會留下永遠轉圈的「驗證中…」）
  - `onBeforeUnmount` 清掉 timer
  - 提示文字：busy 時「正在用 Face ID 辨識…」

### WebAuthn 關鍵事實（查證過，別再猜）
- **iOS 17.4 起 Apple 取消「WebAuthn 需要使用者手勢」**（改成速率限制）→ 可以自動呼叫。
- **iOS 16～17.3**：每次「頁面載入」允許**一次**不用手勢的 `credentials.get()`；
  **SPA 內不會重置**（只有整頁重新載入才會）→ 自動嘗試只能做一次。
- ⚠⚠ **iOS 的「使用通行密鑰登入」面板無法由網頁移除**：web.dev 明載
  「iCloud Keychain 建立的所有 WebAuthn 憑證都是同步通行密鑰，RP **無法**建立
  non-discoverable 或裝置綁定的憑證」→ 改 `residentKey` 也躲不掉，是系統層 UI。
  要零面板只能做原生 App（`LocalAuthentication`）。

### 驗證
- `.smoke/v155.mjs`（**新守門員，14 斷言**）：用 **CDP 虛擬平台驗證器**
  （`WebAuthn.enable` ＋ `addVirtualAuthenticator{transport:'internal', isUserVerified:true}`）
  假裝有 Face ID → 註冊憑證 → 寫入 faceid 設定 → 重整 → **測試全程不點任何東西** →
  鎖屏出現後自己解鎖（`__sawLock=true`、`overlay=false`、`get()` 只呼叫 1 次）。
  另驗「立即上鎖後 1.3 秒仍鎖著」與「手動按鈕仍可用」。
- `.smoke/v154.mjs` 加 6 條 ⑧b 斷言（合計 **45**）：桌機沒有平台驗證器 → 不卡「驗證中…」、
  自動失敗不出紅字、`get()` 最多 1 次、仍可用 PIN 備用。
- 全回歸 **79 支**（v70~v155）。

### 教訓
- 升版要一次改完 v132~v155 ＋ `-live` 的版本斷言（`sed -i 's/0\.1\.83/0.1.84/g' .smoke/v1*.mjs`）。
- **按鈕事件不要直接綁帶預設參數的函式**：`@click="tryFaceId"` 會把 MouseEvent 當第一個參數。
- 自動觸發 WebAuthn 前若還要 await 別的 async，要確認「沒有平台驗證器」時**先退出**，
  否則 headless／桌機會卡在「驗證中…」90 秒（舊版本就踩過）。
