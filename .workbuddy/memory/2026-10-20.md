### `.dotp` 的取捨（花最多時間的一項，別重來）
需求 7（小數點縮小）與 v82（0.1.27：「11 位數＋小數點＝12 字元不能溢出」）**同時成立**，
但桌機等寬字體的 `.` 本來就只佔 ≈0.12em → 把點包成元素必然讓排版變寬。實測序列：
- `inline-block` + font-size 0.62em → 溢出 2px
- `inline` + margin -0.17em → 溢出 4px（負 margin 對 `scrollWidth` **不可靠**）
- `inline-block` + `width:0` + `overflow:visible` → 溢出 12px（**可見內容會被算進 scrollable overflow**，更糟）
- `inline-block` + 0.42em + `margin:0 -3px` → 溢出 3px；改 -5px → 溢出 5px（反效果）
- 最終 `inline-block` + `font-size:0.2em` + `letter-spacing:0` → **不溢出** ✓
量測技巧：`el.scrollWidth - el.clientWidth`；子節點寬度用 `Range.selectNodeContents()` 量
（inline 文字節點沒有 `getBoundingClientRect`）。

### 教訓
- Vue template 的 inline handler **不能寫多行語句**（`@close="a = null\nb = null"` 會 build 爆）→ 抽成函式
- 量字體寬度別用 `style.font = getComputedStyle().font`（shorthand 會解析掉字級）→ 逐項指定 fontFamily/fontSize
- `settings.$patch` 是巢狀的 → 要 `$patch((s) => { s.state.xxx = v })`；讀設定是 `settings.state.xxx` 不是 `settings.xxx`
- 改舊測試的選擇器前先想清楚「它是不是在測**舊行為**」：v106/v116 的失敗都是需求 5／9／10 帶來的
  新語意，測試要跟著改；v84 是純粹的既有紅燈 → stash 驗證後回報，不動它
