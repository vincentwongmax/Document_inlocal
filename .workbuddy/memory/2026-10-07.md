## 計算機彈窗：滑動時背景不能動（commit `58e70b0`）

- 使用者需求：「計算機的頁面，用戶滑動時，背景不要滑動」
- ⚠ **意外挖到更嚴重的 bug**：只給 html 加 `overflow: hidden` 時，Chrome 會把 scrollTop
  **歸零** → 開彈窗背景直接跳回最上面，**關掉也回不去**（實測 80 → 0 → 0）。
  這大概就是使用者感覺背景「跑掉」的主因
- `src/composables/useScrollLock.ts` 重寫成三段一起做：
  1. `html.is-locked { overflow: hidden }`（擋滑鼠滾輪／觸控板）
  2. **body 變 `position: fixed; top: -savedY; left/right: 0; width: 100%`**
     → 畫面留在原地、不會被歸零；這也是 iOS Safari 唯一擋得住手指滑動的做法
     （iOS 不吃 html 的 overflow: hidden）
  3. `touchmove` 非 passive + preventDefault（補強；手指在非可捲動區滑動一律擋）
- 新增 option：`useScrollLock(open, { scrollable: () => el })` → 只有在那個元素裡滑動放行
  - 計算機：不傳（整頁都不捲）；分類彈窗：`.catsheet__body`；記錄明細：`.sheet__body`
  - ⚠ 不要在彈窗最外層設 `touch-action: none` 又希望內層能捲：touch-action 是
    **由目標往上交集**，祖先設 none 會把子孫的 pan-y 一起取消
    （所以只在 `.calcwrap` 設 none，分類／明細靠 touchmove preventDefault）
- 模組層用 `locks` 計數器 + `savedY`：記帳頁同時掛著計算機與分類彈窗，
  只有第一個上鎖／最後一個解鎖才動 body，避免巢狀彈窗互相覆蓋位置
- `src/style.css` 的 `html.is-locked` 加 `overscroll-behavior: none`（額外保險）
- 驗證：`.smoke/v75.mjs` **39/39**（含 CDP 真實 touch 滑動、cancelable touchmove 的
  defaultPrevented、背景視覺位置不變、關閉後位置還原、三個彈窗都測）；
  v70 40／v71 31／v72 18／v74 21 回歸全過
- ⚠ 測這個時別用 `scrollTop` 判斷：body 變 fixed 後 scrollTop 本來就是 0，
  要量「元素相對視窗的位置」（`.pad` 的 rect.top）才代表畫面實際在哪

## iOS PWA：連點按鈕會一直往下捲（commit `0a731f8`）

- 使用者回報：「在 PWA(iPhone)，用戶連續點擊同一個按鈕時，會不停地向下滾動，用戶不需要滾動」
  → 確認是**每顆按鈕都會**（不是單一顆），且**正常手指滑動還是要能捲**
- 先排除程式造成的：沒有 `scrollIntoView`／`scrollTo`、路由沒有 `scrollBehavior`、
  toast 是 `position: fixed`。所以是 iOS WebKit 的手勢問題
- 成因：快速連點被 WebKit 判成 **double-tap**，觸發放大／把畫面帶走
- 改 `src/style.css`（全域）：
  - `html { touch-action: manipulation }` → 只關掉 double-tap 放大，**平移與兩指縮放照常**
    （touch-action 是由目標往上交集，放 html 就涵蓋所有子孫）
  - `button, [role='button'], a { touch-action: manipulation; -webkit-touch-callout: none;
    user-select: none; -webkit-user-select: none }`
    - ⚠ **不要把 `user-select: none` 套到 `label`**：iOS Safari 會把它繼承進裡面的 input，
      備註／金額輸入框會變得不能選字（踩過這個坑，所以只套按鈕類）
    - touch-action 不是繼承屬性，寫在元素本身才好驗（getComputedStyle 才讀得到）
  - `.calcwrap` 的 `touch-action: none` 沒被蓋掉（交集後仍是 none）；可捲區（分類／明細）不受影響
- 驗證：`.smoke/v76.mjs` **17/17**（連點 6 次畫面位置／縮放都不變、連點功能正常、
  正常滑動仍能捲 0→109）；v70 40／v71 31／v72 18／v74 21／v75 39 回歸全過
- 若實機還會：可再加 viewport 的 `user-scalable=no`（iOS Safari 會忽略，但 standalone PWA 有機會吃）

## 版本號機制：設定頁顯示＋CHANGELOG（0.1.0 → 0.1.1）

- 使用者需求（原話）：「之後的每次更新都加入版本號，如果沒有說的話就 x.y.z (只增加Z)，
  大版本我會跟你說升級X 或Y，在設定頁要顯示，文件也要記錄每次升級了什麼」
  → 定成長期慣例，見 MEMORY.md「版本號與變更紀錄」
- 做法（版本號**單一來源＝`package.json` 的 `version`**，不另外維護字串）：
  - `vite.config.ts`：`readFileSync(package.json)` 取 version，加
    `define: { __APP_VERSION__: JSON.stringify(pkg.version) }` 注入
  - `env.d.ts`：`declare const __APP_VERSION__: string`（這個檔在 tsconfig 的 include 裡，
    且沒有頂層 import/export，所以是**全域宣告**）
  - 新增 `src/lib/version.ts`：`export const APP_VERSION: string = __APP_VERSION__`
  - `src/views/SettingsView.vue`：「離線使用」區塊**改名「離線與版本」**，
    「版本」那一列改成 `<div class="ver">`（膠囊 `v{{ APP_VERSION }}` + 原本的「檢查更新」鈕）
    - ⚠ 容器一定要用 **`div` 不是 `span`**：全域 `.row > span`
      有 `flex-direction: column`，用 span 會把膠囊擠到按鈕**上面**（`.ver` 選取器權重 0,1,0
      打不過 `.row > span` 的 0,1,1）
- 新增 `CHANGELOG.md`：頂端寫版本規則（Z 預設自動 +1、Y/X 使用者明說才動）＋
  「版本號單一來源是 package.json」的說明；`[0.1.1]` 收錄這批六項修正（統計幣別、日期對齊、
  彈窗鎖背景、iOS 連點、圖片壓縮、計算機鍵盤）＋版本號顯示本身；`[0.1.0]` 是初始版本
  - 六項修正**先於版本號機制完成**，統整在 0.1.1 一併記錄（已在 CHANGELOG 註明）

### ⚠ 兩個踩到的坑（都很值得記）

1. **`npm install sweetalert2` 把 `@esbuild/win32-x64` 移掉了** → `npm run build` 直接爆
   `The package "@esbuild/win32-x64" could not be found, and is needed by esbuild`。

   `npm install @esbuild/win32-x64@0.28.2` 會把它寫進 dependencies（不該如此）。
   正解：**把該行從 package.json 刪掉、再跑一次 `npm install`**，npm 就會照 esbuild 的
   optionalDependencies 把它裝回來（`node_modules/@esbuild/win32-x64` 在、package.json 乾淨）
2. **SweetAlert2 官方 CSS 不要自己 import**：套件入口是 `sweetalert2.all.js`，
   執行時會把**整份 CSS 插成 `<head>` 裡的一個行內 `<style>`**，而且插在我們所有 `<link>`
   之後 —— 文件順序在後，**同權重就會贏過 style.css**。所以「底部 Toast 往上讓開導航列」
   這條唯一的覆寫**必須加 `!important`**。
   - 我先是照慣例 import 了 `sweetalert2/dist/sweetalert2.min.css` 並把它排在 style.css 前，

   - 診斷方式：把 `document.styleSheets` 裡所有含 `swal2-container` 且帶 `bottom|inset` 的
     規則全部列出來 → 看到多了一個 `inline` sheet 帶著完整 SweetAlert CSS
   - ⚠ 寫這個 walker 時要注意：**Chrome 120+ 的 `CSSStyleRule` 也有 `cssRules`**（巢狀規則），
     用 `if (r.cssRules) { recurse; continue }` 會把正常的樣式規則整批跳過 → 要改成

## 0.1.3：計算機 11 位上限 ＋ 日期框在 iPhone PWA 的高度（commit `faba9df`）

### 1. 計算機：只顯示 11 個位，第 12 位不要出現

- 使用者的理由很明確：**不想看到字級被縮小**
- 關鍵決定：**第 12 位讓它「不進狀態」，而不是「收下但遮住」**
  - 若只截斷顯示，畫面顯示 11 位、實際記下的卻是 12 位 → 帳目對不上，比縮字級更糟
  - 改 `src/lib/calc.ts` 的 `input()`：數字 token 的位數上限 `12 → 11`
    （`.` 與 `-` 不佔額度：`last.v.replace(/[.\-]/g, '')`）
- **縮字級的門檻要跟著放寬**，否則 11 位＋小數點（12 字元）還是會縮：
  原本 `display.value.length > 11` → 改成 `> 12`
  - 順手把這段重複邏輯抽成 `lib/calc.ts` 的 **`isLongDisplay()`**，
    `CalcSheet.vue` 與 `HomeView.vue` 都有同一份 `displayLong`（各自 11 有兩份＝一定會走樣）
  - ⚠ 兩處基準字級不同：計算機 `.calcdisp__num` 38px（long 24px）、
    首頁 `.amount__num` 32px（long 22px）—— 寫測試時別把 38 當成兩邊都對
- 驗證 `.smoke/v82.mjs`：按 12 次只有 11 位、字級 38px、`is-long` 沒出現、無溢出；
  小數點／負號版本（12 字元）也不縮；長公式（25 字元）仍會縮（保護還在）

### 2. 日期輸入框在 iPhone PWA 比備註框高

- 真正原因（查到的權威說法，不是我猜的）：**Safari 把 `date` / `datetime-local` 拆成
  shadow DOM 的多個小欄位（年、月、日、時、分…），每個欄位都自帶 padding**，
  整個輸入框於是比一般文字框高 → 跟旁邊的備註欄對不齊
  （來源：<https://gomakethings.com/articles/fixing-temporal-input-styling-in-safari/>）
- 修法：把 `::-webkit-datetime-edit*` 那批內部欄位的 **padding 歸零**，
  再用 `height` ＋ **`min-height`** 把高度鎖成 `.field` 的 42px
  - ⚠ **`min-height` 一定要一起寫**：Safari 的 UA 樣式有最小高度，只寫 `height` 會被壓過去
  - ⚠ 這些 `::-webkit-datetime-edit*` 在 Chrome 也支援、預設內距本來就是 0 → 設 0 無副作用，
    所以**不需要**用 `@supports` 去偵測 iOS
  - ⚠ **不要用 `-webkit-appearance: none`**：會把 Chrome 的原生日曆鈕一起關掉
    （實測 `getComputedStyle().webkitAppearance` 仍是 `auto`，原生控制項保留）
- **做在 `style.css` 的 `.field` 上，不是 `DateTimeField.vue`**：
  因為記錄頁（日期範圍）與統計頁（monthbar／自訂範圍）用的是原生 `type="date"`，
  沒經過 `DateTimeField`，只改元件會漏掉這兩頁
- 驗證 `.smoke/v82.mjs`：三頁的日期框與文字框**實際量到都是 42px**、
  `min-height` 計算是 42px、樣式表裡真的有那兩條規則
